### Settled Product Owner decisions

- **W1:** Admin has a distinct explicit issue/revoke/reassign capability for one individually authenticated examination-scoped Radiographer workspace. Generic Admin-read capability never authorizes these commands.
- **W2:** Assigned Radiographer can inspect original DICOM, verify/correct separate technical metadata, record technical QC and hand off. No raw DICOM download action, diagnostic reporting, AI report access or original-DICOM mutation.
- **W3:** Admin selects 24 hours, 3 days or 7 days; default 24 hours, maximum 7 days. Exact actor/case/site/action checks on every protected request, immediate revocation/reassignment enforcement; handed-off case is read-only until expiry/revocation.
- **W4:** Autofill from verified sources, label authoritative versus fallback data; reconcile actual Study/Series/SOP UIDs. QC states are **Layak**, **Tidak Layak**, **Perlu Eskalasi**. No automatic retake. Complete metadata plus approved QC permits immutable-version-bound, atomic, idempotent, attributable handoff into pending radiologist review; Admin assigns Radiologist later. Recorded Admin authorization permits controlled reopen while preserving prior QC; no clinically finalized-report change. Direct Grabber, manual NPZ/MPIPS, Operator behavior and independent AI dispatch remain intact.
- **W5.1:** Audit issuance, revocation, reads, protected DICOM delivery, metadata/QC writes, handoff, reopen and denied actions. Minimize sensitive content; required audit failure blocks disclosure or rolls back mutation.
- **W5.2:** All development fixtures synthetic. Production audit retention, operational access, applicable regulatory obligations and G10 authorization remain unresolved separately. Do not borrow approval from unrelated MVP-04I policies.

### Access and authentication contract

1. Proposed explicit capability names: `operator.radiographer-workspace.issue`, `.revoke`, `.reassign`, `.reopen` (full prefix applies to each). Each is checked independently with fresh eligible Admin status and managed case/site scope. Final identifiers may follow house vocabulary without changing distinct action authority. No role/read permission implies a grant; no automatic seeder or broad role expansion.
2. Use a persisted examination entitlement and Laravel temporary signed **entry** URL containing opaque entitlement ID/generation/expiry only. Link is a locator with tamper/expiry protection, never a bearer clinical credential. No MRN/name/NIK, case tuple, role grant, storage URL or object token in it. Admin copies it for existing operational distribution; no messaging automation or external connector.
3. Reuse individual Laravel web User credentials/session with explicit eligible Radiographer entry. Neutral unauthenticated login; rate limiting, CSRF, session rotation, allowlisted same-origin return path, logout/password-change restrictions. No new OTP, identity provider or password-reset-as-invitation mechanism. Authentication does not grant legacy Operator/AI access.
4. Proposed expiry anchor is issuance transaction time, measured as elapsed UTC 24/72/168 hours; access valid on `[issued_at, expires_at)`, never extended by login/handoff/reopen. Reassignment atomically revokes the old generation and issues a new selected lifetime (default 24h), without resetting QC/history. Copying the same link does not renew it. Expired/revoked access requires a separately audited issuance. Review approves these anchor/reissue details, not the already settled W3 durations.
5. Every protected HTML/JSON/Livewire/image/service/write request checks persisted actor/account/eligibility, exact case/site, generation, action and time, owner associations, integrity and current version. Browser/session claims and cached worklist rows are insufficient. Checks and writes serialize against revoke/reassign; whichever commits first establishes ordering. After a revocation/reassignment commit, no old-generation request may newly disclose or mutate. No eventual cache propagation or TTL-only enforcement. Already transmitted bytes cannot be recalled.
6. Guest/wrong/expired/revoked/guessed links produce the same neutral unavailable entry without patient/case-existence leakage. GET/link scanner never issues, consumes, hands off or reopens. After login, use a clean URL; forwarded URL remains unusable by any other actor. Mixed-case tabs are independently authorized.
7. Protected responses use private/no-store, nosniff, no-referrer and appropriate secure/HttpOnly/SameSite cookies over HTTPS; no external analytics/resources on entry/workspace. Redact signed entry URLs from logs/referrers. Object grants stay server-side and cannot outlive entitlement/action authority. Clear viewer/disable writes when denial is detected; every subsequent network request still checks authorization.

### Immutable DICOM and UID verification contract

- Gateway binds inspection to `{MHCS study ID, capture ID, private object identity/version, SHA-256, byte size, actual StudyInstanceUID, SeriesInstanceUID, SOPInstanceUID, SOPClassUID, file-meta SOP identity, transfer syntax, frame/instance inventory, verification revision}`. Public projections exclude private storage identity. Metadata/QC never modifies these facts.
- Parse the stored bytes on the trusted server after assignment authorization, with size/time/memory limits, strict UID/file-meta validation, safe character-set handling and supported transfer-syntax/frame policy. Verify checksum/length before parsing. Existing `dicom-parser` 1.8.21 is installed and supports Node; prefer bounded reuse behind Gateway if technical owner approves its server runtime and validation coverage. Browser parsing is display assistance only. No handwritten full DICOM parser, new dependency or remote MPIPS/AI call for each read. Missing runtime/unsupported encoding fails safely and returns to planning if required accepted cases cannot be supported.
- Reconciliation records actual UIDs alongside existing MHCS column values and provenance. A known direct `grabber:*:<MHCS-study-id>` derived identifier is a **record alias**, not the object's UID. The proposed safe legacy disposition recognizes only proven source-path/algorithm aliases with verified patient/case/object association; it does not overwrite UID columns or original bytes. Unknown drift, duplicate actual SOP UID with different bytes/case, manifest/actual UID conflict, absent/invalid UID, file-meta mismatch or corrupt association blocks successful QC/handoff and withholds image disclosure where identity is unsafe. Algorithm resemblance alone is not proof of provenance.
- Legacy NPZ path additionally reconciles expected resolved UIDs against actual output and original signed manifest. Omitted UIDs may be regenerated from verified MPIPS job identity; explicitly supplied UIDs take precedence and must match bytes. Do not treat successful HTTP response/DICM signature as dataset validation.
- PatientID/MRN and supplied accession/study references must agree with owner-resolved case. Name/DOB/sex contradictions, unverified external-ID mapping or uncertain subject association are held for escalation before image disclosure; formatting normalization must not erase a substantive discrepancy. Unknown non-identity technical fields may remain visibly incomplete. No Radiographer override can reassociate patients or edit demographics/UIDs. Admin receives minimized discrepancy status; owner correction outside this workspace must produce new verified evidence.
- Received DICOM bytes, capture source/manifest/signature, AI inputs/reports and prior QC/history are immutable here. A new source/object/checksum/UID/identity binding invalidates the current approval; prior history remains tied to the old version. No real-data backfill or blanket “repair UIDs” operation is authorized.
- Proposed first supported scope is an existing **single-object, single-frame radiographic examination whose complete required image set is evidenced**. Single database object does not prove whole-exam completeness. Missing views, multi-instance/multi-series/multiframe, unreadable or unsupported cases receive unavailable/escalation and cannot be handed off as complete. B2 must approve supported exam kinds/required views; multi-instance PACS redesign is excluded.

### Persistence, concurrency, handoff and reopen

Minimal additive owner records are needed for entitlement generations, Gateway verification snapshots, technical overlay/QC revisions, Admin reopen authorization and immutable handoffs/idempotency. Keep existing capture/study/queue/report schema semantics. Reuse database transactions, unique constraints, optimistic revisions and row locks rather than a parallel event-store/state-machine framework. No cascading deletion of history. Production migration/backfill execution is separately unauthorized.

**QC cycle:** unreviewed → recorded outcome. Only complete approved checklist + Layak + safe identity/UID reconciliation + current eligible assignment + exact current metadata/QC/source version can create a handoff. It stores immutable byte/UID binding, overlay/QC/checklist version, case/site, Radiographer, time, entitlement generation and pending-review status. No radiologist ID is fabricated. AI success/failure does not gate handoff. Pending radiologist review is an Operator technical handoff state; it does not transition legacy ingestion/queue, clinical finalization or publication.

**Atomic handoff:** within one transaction serialize entitlement/generation, current QC revision, verification/current study binding and clinical-finalization guard as applicable; freshly authorize; validate; append handoff and audit plus idempotency result. No partially committed handoff, status, audit or response. Read-only mode begins only on committed handoff. Same current authorized actor/key/payload retry returns the same handoff without duplicate event; conflicting payload/key or stale cycle/version fails without overwriting. A replay after expiry/revocation/reassignment cannot retrieve a historical success or renew access. Unique active handoff per case/source/QC cycle prevents concurrent double submission. All mutation/audit/commit failures roll back. Revision changes race safely with save/handoff and force review of the new version.

**After handoff:** assigned Radiographer can inspect authorized images and the submitted overlay/QC read-only until expiry/revocation. Admin assignment to Radiologist is later work. Revoke/reassign does not delete handoff or grant the former assignee continuing access.

**Controlled reopen:** separate fresh Admin `.reopen` capability, exact case/site, recorded reason and reference to prior handoff; verify no clinically finalized report, fail closed if status cannot be established. Atomically append Admin authorization, supersede current pending eligibility and start a new QC cycle, preserving original handoff/QC/actor/time. It does not restore revoked/expired entitlements or extend expiry; current assigned Radiographer writes only under independently valid access and the reopened cycle. Later Doctor consumers must reject superseded handoffs. No amendment, signature, finalized-report or AI-report mutation. Unknown future Doctor state is a stop/withhold condition, not assumed absence. Reassignment alone is not reopen.

### Required audit contract

One durable success event per authorized protected HTTP disclosure (HTML/JSON/Livewire and each DICOM delivery, including supported range/cache-related response); internally repeated owner calls may share the same correlation, but bypass/service tests must prove no unaudited disclosure. Audit actor, trusted internal case/site reference, entitlement generation, action/outcome, revision/digests, UTC time/correlation and minimized reason code. Proposed vocabulary: `radiographer-workspace.issued|revoked|reassigned|read|dicom-delivered|metadata-saved|qc-recorded|handed-off|reopened|denied`. Authentication outcomes reuse sanitized security events.

Never audit credentials, signatures/full URLs, raw DICOM/header values, MRN/NIK/names/DOB, free-text QC, object keys/grants or clinical content. Generic denial for anonymous/invalid scope must not resolve PHI merely to audit; case attribution only after trusted resolution. Do not trust client actor/case/site fields. Detailed overlay and QC history remain separately access-controlled domain data.

Successful reads require audit commit before serialization/byte delivery and fresh authorization at delivery ordering; required audit append/commit failure returns unavailable with no protected bytes or stale values. Mutations and success audit commit together. Denied requests stay denied; if denial audit fails, return generic unavailable and disclose/mutate nothing. Do not fall back to successful response, best-effort success logging, delayed audit/outbox as a disclosure substitute or partial streaming before the gate. Audit records delivery authorization/start, not proof the remote viewer fully received or inspected it.
